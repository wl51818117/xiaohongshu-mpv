> 日期：2026-10-04
> 王哥需求：**程序登录小红书（内置 Web），把「自己号的爆款文章」加入素材库，用于二次创作**
> 本文是对 06 号文档（v2）的增补，不替代它

## 一、先划一条线：这是合规的，但有前提

### 1.1 为什么「自己的号」性质完全不同

| 对象 | 性质 | 风险 |
|---|---|---|
| 爬**别人**的笔记 | 侵犯数据权益、绕技术措施 | 🔴 判刑三年 / 判赔 110 万 |
| 爬**自己**的笔记 | **自己的数据** | 🟢 低风险 |

**关键区别**：自有账号的内容本来就是自己生产的，程序只是把「已在创作者后台能看到的数据」自动化。这是**数据搬运，不是数据获取**。

### 1.2 ⚠️ 但「二次创作」不等于「直接重发」

这是本方案最大的风险点。2026 新规对**站内搬运**的打击：

| 行为 | 判定| 后果 |
|---|---|---|
| 站内搬运他人笔记、图片/视频，伪装原创 | **侵权** | 限流甚至封号 |
| 同一内容多账号重复发布 | 系统比对**图片指纹 + 文字相似度，超 60% 即判抄袭** | **所有相关账号一起降权** |
| 矩阵账号发完全相同内容 | 协同判定 | 降权 |
| 主账号关联超 3 个子账号 | 2025 新规明确违规 | 关联矩阵号同步处罚 |

**真实案例**：一位做矩阵的客户**一夜之间 37 个账号接连被处置**，连养号阶段的小号也没幸免。

### 1.3 所以正确姿势是

```
✅ 采集自己账号的爆款  → 提炼「选题方向 + 结构模板 + 爆款要素」
✅ 二次创作            → 换角度 / 换人群 / 换场景 / 补新信息
❌ 直接复制原文重发     → 文字相似度超 60% = 抄袭
❌ 多账号发同一篇       → 60% 相似度判定 + 账号关联处罚
```

**一句话**：**学结构，不抄文字；换维度，不换皮。**

## 二、技术方案（已验证可行）

### 2.1 ⭐ 首选：XHS-Downloader（12,898 star）

| 项 | 信息 |
|---|---|
| 仓库 | `JoeanAmier/XHS-Downloader` |
| Star | **12,898**（本方案调研中最高，2026-10-04 仍在更新）|
| 部署 | **Docker / TUI / API / MCP 四种模式** |
| 登录 | **Cookie 非必需**（配置后画质更高；Windows 需管理员权限读浏览器 Cookie）|
| 数据落库 | SQLite（`ExploreData.db`）|

**为什么它是本方案的基石**：

```
✅ 用户脚本能「提取账号发布作品链接」（自动滚动加载全部）
   → 这正是「把自己号的爆款全捞出来」的能力

✅ 支持 MCP 模式（Streamable HTTP）
   → 我们的 dsh 内核可以直接挂 MCP！tools/index.js 已验证支持
   → 内核里已有 dsh-mcp-client，加几行 YAML 就能接

✅ 支持 API 模式
   → 也能用 REST 调

✅ 作品信息可存 Markdown/txt（note_format）
   → 正好喂给我们的 AI 二次创作环节

✅ 内置请求延时机制（作者明确写了为避免频率过高）
```

**三个必须知道的细节（作者原话）**：
1. ⚠️ **作品链接携带日期信息**，用旧日期的链接可能触发风控 → **要用最新获取的链接**
2. ⚠️ **自动滚动功能默认关闭**，作者警告「启用可能被小红书检测为自动化操作，导致账号受到风控或封禁风险」
3. ⚠️ Windows 读Chrome/Edge Cookie **需要管理员权限**

**接入 harness 的方式**（我们已验证内核支持 MCP）：
```yaml
# cordis.patch.yml 加：
- insert:
    - id: mcp-xhs
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        transport: streamable-http
        serverName: xhs
        url: 'http://127.0.0.1:5556/mcp/'
```
→ 内核里直接多出 `mcp__xhs__*` 工具，Agent 可按需调用。

## 三、M1 采集中心最终设计（三源合一）

### 3.1 三个采集源

```
源1：RSS / 新闻源        （王哥已有）    → 行业资讯、热点事件
源2：自有账号爆款回采    （v3 新增）    → 自己已验证有效的选题与结构
源3：全网热点聚合（可选）                → 平台热榜、跨平台话题
         ↓
    统一进原始素材库 raw_materials
         ↓
    AI 二次创作层（关键）
         ↓
    可执行选题 topics
```

### 3.2 统一素材库表设计

| 字段 | 说明 | 来源标识 |
|---|---|---|
| `source_type` | `rss` / `own_note` / `hot_list` | 三源区分 |
| `source_url` | 原文链接 | 溯源用 |
| `title` | 标题 | |
| `raw_content` | 原文/正文 | |
| `metrics` | 互动数据（**仅 own_note 有真实值**）| |
| `publish_time` | 发布时间 | |
| `own_flag` | **是否自己的账号** | 🔴 合规关键字段 |
| `originality_risk` | 原创风险等级 | 二次创作前必读 |
| `extracted_elements` | AI 提炼的要素 | 见下 |

**AI 从自有爆款里该提炼什么**（不是原文，是要素）：

| 要素 | 说明 |
|---|---|
| `topic_direction` | 选题方向（不是标题本身）|
| `structure_template` | 结构模板（钩子类型/段落顺序）|
| `title_formula` | 标题公式（用了哪种）|
| `cover_type` | 封面类型 |
| `why_it_worked` | 为什么会火（机制分析）|
| `portable_elements` | **可移植的部分**（❌ 不可移植：具体数据、案例、个人经历）|

### 3.3 二次创作的硬性约束（写进 skill）

```
输入：一篇自有爆款笔记
输出：一篇新笔记

必须做的差异化（四选至少三项）：
 1. 换人群：同一问题，面向不同人群
 2. 换场景：同一方法，不同使用场景
 3. 换角度：从反面/对比/进阶切入
 4. 补增量：加原文没有的新信息、新数据、新步骤

严禁：
 ✗ 直接复用原标题结构
 ✗ 复用原文的案例、个人经历、数据
 ✗ 文字相似度超 60%（平台判定抄袭线）

强制：
 ✓ AI 声明必标
 ✓ 原创度自查（>70% 同质化判低质）
```

### 3.4 多账号复用的正确姿势

⚠️ 平台红线（务必守住）：

| 规则 | 阈值 |
|---|---|
| 文字相似度 | **超 60% 即判抄袭** |
| 主账号关联子账号数 | **超 3 个即违规** |
| 矩阵号发相同内容 | 协同判定，**所有相关账号一起降权** |

**安全做法**：
```
同一选题 → 同一个内容内核 → 生成 N 个差异化变体
每个变体：不同标题公式 + 不同角度 + 不同案例 + 分散发布时间

❌ 不是：一篇稿复制到 5 个号
✅ 而是：一个内核 → AI 生成 5 个差异化版本
```

**发布节奏也要分散**（调研结论）：统一整点发布 → 被判机器化批量铺货 → 压缩推荐池。建议间隔 **20-90 分钟随机偏移**。
