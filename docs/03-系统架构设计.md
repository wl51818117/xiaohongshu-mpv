# 电商工作台 · 系统架构设计

> 定位：把「小红书内容运营」从人工串流程，变成 Agent 编排的内容工厂。
> 核心设计原则：**AI 干可逆的活，人守不可逆的关。**

## 二、七大模块划分

| # | 模块 | 职责 | 核心产出 |
|---|---|---|---|
| M1 | **采集中心** | 爆款选题与数据抓取 | 选题候选池 |
| M2 | **选题库** | 选题入库、分类、评分、占用 | 可执行选题 |
| M3 | **文案工坊** | AI 生成/改写/去 AI 味 | 稿件正文 |
| M4 | **素材工厂** | AI 生图（封面/内页）、AI 生视频 | 素材包 |
| M5 | **组合发布** | 图文包 / 视频包组装、一键投递| 发布任务 |
| M6 | **发布代理** | 半自动填充、人工确认、状态回写 | 平台笔记 |
| M7 | **数据看板** | 数据回流、复盘、爆文复用 | 决策依据 |

**贯穿性横切模块**（不占 M 编号但必须有）：

| 横切 | 职责 | 为什么独立 |
|---|---|---|
| **X1 AI Provider 抽象层** | 统一生图/生视频/生文本的调用、计费、模型热切换 | 模型会下线（可灵 2026-09 已批量下线），硬编码必返工 |
| **X2 规格校验器** | 图文/视频 12 项硬规格确定性校验 | 规则化校验是**最容易做出真实价值**的部分 |
| **X3 合规校验器** | 违禁词/站外导流/AI 标识/同质化| 平台红线，拦截器 |
| **X4 素材库** | 对象存储 + 版本 + 生命周期提醒 | AI 素材生命周期仅 15 天，需提醒换新 |

### M1 采集中心

| 采集源 | 可获取字段 | 方式 | 风险 |
|---|---|---|---|
| 搜索下拉词 | 联想词、搜索热度趋势 | 浏览器插件/人工录入 | 低 |
| 爆文榜单 | 笔记标题、赞藏评、话题、博主、发布时间 | **第三方数据平台（新红/千瓜/灰豚）** | 低（买数据） |
| 竞品账号 | 近期笔记列表、爆款规律 | 第三方平台 | 低 |
| 评论区提问 | 高频问题 → 直接转选题 | 采集已获取笔记的评论 | 低 |
| 平台热点 | 创作中心热门话题 | 创作者中心人工/半自动 | 低 |
| 关键词热度 | 月搜索量、竞争热度、建议出价 | **聚光关键词规划工具（官方口径）** | 低 |

**设计要点**：采集是"半自动"而非"全自动爬"。官方开放平台**没有内容类目**（只有一键搬家/商品优化/打单/订单/ERP/商家后台），拿不到笔记数据。

⚠️ **自建爬虫有刑事判例**：2024 年陈某等三人破解小红书加密算法非法获取用户数据，**判有期徒刑三年**；2025 上海知产法院二审爬取笔记数据售卖案**判赔 110 万**。
→ **主路径 = 第三方付费 API；明确不自研爬虫。**

**输出**：`candidate_topics` 表，字段：标题、来源、赛道、热度分、竞争度、采集时间、原文链接、原始截图。
**注意**：第三方互动数据是**估算值**，同一账号不同工具可差 72%，产品内必须标注。

### M2 选题库

**量化筛选模型（可直接落库）**：

```
选题因子叠加：人群 × 场景 × 痛点 × 形式
例：上班族 × 办公室 × 不长胖 × 食谱
九宫格法（3×3）可一次性产出几十个候选
```

| 字段 | 判据 |
|---|---|
| 竞争度 | 同题笔记 **≤10 篇=蓝海（优先）**；>50 篇=红海（慎选） |
| 实操验证 | 搜该词看**前 20 篇**的日期与互动量，若大量高互动老笔记 → 壁垒已高，新号不宜正面进|
| 关键词分层 | 核心词（月搜1万+）/ **长尾词（1000-1万，性价比最高）**/ 蓝海词 |
| 价值类型 | 情绪/实用/信息/经济（至少占1 种） |
| 痛点信号词 | `求推荐` `怎么买` `多少钱` `适合XX吗` `和XX比哪个好` |
| 选题配比 | **纯流量 : 变现= 7 : 3** |

**⚠️ 2026 最重要的变化是「搜索流量 + 语义理解」双升级**，不是 CES 权重。搜索流量占比逼近 50%，约 30% 用户打开 App 直接搜索。
→ **选题系统应从「追热点」转向「长尾词布局」**。

**内容配比**：干货 70% / 热点 20% / 人设 10%（商业笔记 ≤20%）

**状态机**：`draft`（采集）→ `pooled`（入库）→ `claimed`（占用建稿）→ `done`（成稿）

### M3 文案工坊

三段式生成 + 去 AI 味两遍：

```
选题 + 关键词 + 埋词要求 → 初稿（AI 生成）
   ↓ 去 AI 味改写（口语化 + 个人视角 + 真实细节）
   ↓ 合规校验（极限词/虚假/导流/同质化）
终稿（人审后定稿）
```

**标题硬约束**：**≤20 字**，**前 8-13 字必须含核心长尾词**（搜索权重第一来源）。
**正文硬约束**：300-800 字，**前 80 字埋词**（否则被折叠）；首行不留空格缩进（会被判机器号）。
**埋词分寸**：2026 语义理解看整体相关性，**核心词自然出现 2-3 次即可，硬堆 5 次触发限流**。

**关键约束**（对应平台红线）：
- 禁止编造个人经历（AI 造假红线）
- 禁止极限词、虚假夸大
- 禁止站外导流话术
- 必须标注 AI 参与
- **同质化 >70% 相似度判低质**，需人工修改 ≥30%

### M4 素材工厂

**图文链路**：封面 3:4 + 内页 4-8 张
- 提示词 5 层次：主体 → 动作情绪 → 环境光影 → 镜头语言 → 风格画质
- 封面出 **3 候选**（点击率 <2.5% 难晋级流量池，多给选择权）
- 一致性四层：Seed（免费但场景变就漂）→ 参考图（主力）→ LoRA（长期金标准）→ 换脸（兜底）
- ⚠️ 参考集需 **8-15 张标准参考图**且**必须人工精选**（畸形图会被永久复现）
- **图内中文大标题**：选 Nano Banana Pro（官方强调 accurate text rendering）；Seedream 需后期叠字

**视频链路**：图生视频（**必选项而非可选项**）
```
分镜脚本（AI 生成） → 首帧图（复用生图）→ 图生视频 → ffmpeg 拼接+字幕+BGM → 独立封面
```
- ⚠️ **T2V 画面不可控，无法保证与封面/商品一致，电商不可用**。图生视频天然让"封面即首帧"，是与生图环节的天然衔接点
- 时长 15-60 秒，前 3 秒强钩子，AI 单镜头 3-5 秒
- 切镜 2-3 秒；每 15 秒给小高潮；字幕避让底部 15%
- 封面单独出，**不要用第一帧**

**长视频机会（2026 扶持）**：中长视频推荐有效期 **90 天**（图文仅 15-20 天），视频初始曝光比图文高约 30%，消费时长同比 +43%。
→ **最优策略：图文 + 视频双轨——图文抢搜索，视频冲推荐，图文爆款可二次改编成视频。**

**技术选型（2026 实际价格）**：

| 能力 | 首选 | 成本 | 备注 |
|---|---|---|---|
| 生图 | **Seedream 4.0** | **¥0.2/张** | 中文提示词最强；日均30篇×3张 ≈ 月 ¥540 |
| 生图（需图内中文） | Nano Banana Pro 2K | $0.134/张 | 文字渲染更好 |
| 图生视频 | **Vidu Q3-turbo 错峰 / Seedance 2.0-mini 720P** | ¥3.8-7.4 / 15秒 | Seedance 2.0 1080P ¥37 较贵 |

> **本机已具备**：WorkBuddy 内置 ImageGen / VideoGen 可先跑通流程，省掉接入与Key 成本。生图约 5-10 积分/张，视频约 50-100 积分/5 秒。规模化再接 API。
> **必须自建 Provider 抽象层**：可灵已于 2026-09-15 批量下线 Kling Image 1.0-2.0 等模型，Seedream 已迭代 4.0→4.5→5.0。硬编码模型 ID 必然返工。

### M5组合发布

**图文包** = 封面 + 3-7 内页 + 标题 + 正文 + 标签 + **AI声明** + POI + 商品关联
**视频包** = 视频 + 独立封面 + 标题 + 正文 + 标签 + **AI声明** + POI + 商品关联

发布前跑 X2 规格校验 + X3 合规校验，任一不通过则拦截。

### M6 发布代理（半自动，设计红线所在）

⚠️ **小红书风控是「事后聚类」而非实时拦截**。已知反爬层次：
`x-s`/`x-t` 签名 → `acw_sc__v2` WAF → CDP 痕迹检测 → Canvas/WebGL 设备指纹 → **鼠标贝塞尔曲线行为指纹** → 陀螺仪微抖动 → 同设备多账号打标。

**关键结论**：即使指纹伪装完美 + 真人账号 + 真住宅 IP，**AI Agent 操控真实浏览器仍会被识别**——反爬厂商已用 mouse dynamics 直接训练分类器，**AI 与人类的运动差异是统计学差异，不是 stealth 插件能补的**。且处置是延迟+概率的。

| 路线 | 实现 | 风险 | 推荐度 |
|---|---|---|---|
| **A. 半自动预填** | Playwright 打开创作页，自动填正文/标签/上传素材，**人工点发布** | 低 | ★★★★★ **主推** |
| B. 全自动发布 | 无头浏览器直接 submit | **高（封号，且规则原文点名"AI托管账号"）** | 禁用 |
| C. 人工发布 | 工作台导出发布包，人肉发 | 无 | 保底 |

**核心设计**：把"内容组装"（可逆、AI 全自动）与"平台提交"（不可逆、人做）彻底分离。
Agent 只做到 `xhs_build_post` 生成发布包并投递队列，**绝不触碰最终提交动作**。

### M7 数据看板

| 周期 | 动作 |
|---|---|
| 日 | 10 分钟过一遍曝光/点击/收藏/涨粉 |
| 周 | 拆解爆文标题、结构、封面规律，淘汰低质方向；**评论区高频提问 → 下一批选题** |
| 月 | 配比校验（7:2:1、商业≤20%）、关键词趋势、**素材是否过 15 天红利期**、标签重合度（<60% 判定位偏离）|

**投流阈值（可直接写进代码做自动建议）**：
| 工具 | 触发条件 |
|---|---|
| 薯条 | 封面点击率 **≥5%** 且完读率 **≥40%** |
| 聚光 | 48h 赞藏 **≥100** 且点击率 **≥3%** |

回流字段：曝光、点击率、互动率、完播率、收藏率、涨粉、转化、**搜后率**
**爆文复用**：数据好的笔记 → 拆解要素 → 生成新选题（闭环回 M2）

### X4 素材新鲜度提醒（易被忽略的运营情报）

滤镜化旧素材掉量明显，**新素材生命周期约 15 天**。同一套封面模板要**每 ~2 周换一次视觉**，否则明显掉量。
→ 系统应对素材打`freshness` 标签，超 15 天提醒换新。

## 三、双链路状态流转（图文 vs 视频）

### 图文链路

```
M1 采集 → [candidate_topics 落地]
   ↓
M2 选题库 → [选题 scored，status=pooled]   ← 人工/规则筛选（含竞争度、蓝海判定）
   ↓
M3 文案工坊 → [title×3（≤20字，前8-13字含长尾词）+ body(300-800字，前80字埋词) + tags + ai_flag]
   ↓ 去AI味（人工改≥30%）→ 合规校验（极限词/导流/同质化<70%）
   status=review_needed   ← 人审
   ↓
M4 素材工厂-生图 → [封面 3候选(3:4) + 内页 4-8张]  status=assets_ready
   ↓ 人挑封面
M5 组合 → [图文发布包]  status=packaged
   ↓ 过 X2规格校验 + X3合规校验（AI 声明必填、POI）
M6 发布代理 → [Playwright 预填 + 人工点发布]  status=submitting → published
   ↓
M7 数据回流 → [metrics 回写] → 爆文要素 → 回流 M2
```

**状态枚举**：`collected` → `pooled` → `claimed` → `writing` → `review_needed` → `assets_ready` → `packaged` → `submitting` → `published` → `archived`

### 视频链路（差异集中在素材与指标）

```
... M1→M2→M3 完全复用（图文的文案与标题逻辑）...
  ↓ 稿件额外产出：分镜 script[]（0-3s钩子 / 3-6s可信 / 6-45s主体 / 45-60s转化）
M4 素材工厂-视频
  → [首帧图生成]          ← 复用生图能力，实现"封面即首帧"
  → [图生视频 per 分镜]    ← 每镜 3-5 秒
  → [ffmpeg 拼接 + 字幕(避让底部15%) + BGM + 独立封面 3:4]  status=assets_ready
  ↓ 人审钩子与分镜
M5 组合 → [视频包：mp4(9:16,1080P,≤500MB) + 封面 + 文案 + AI声明]
  ↓ 过校验（多校验分辨率/码率/时长/前3秒/字幕位置/无水印）
M6 发布代理 → [预填 + 人工确认] → published
  ↓
M7 数据回流（重点看完播率 + 完整播放时长）
```

**两条链路共用的部分（最大化复用）**：
- M1/M2/M3 **完全共用**
- M4 的生图子能力共用（视频首帧 = 生图）
- M5 的合规清单共用（视频多校验几条规格）
- M7 指标结构共用（视频多完播率与完整播放时长）

**只分开的地方**：
| 维度 | 图文 | 视频 |
|---|---|---|
| 素材产出 | 封面 + 4-8 内页（多张图） | 首帧图 + 分镜视频 + 独立封面 |
| 生成方式 | 文生图为主 | **必须图生视频**（T2V 画面不可控，电商不可用）|
| 规格校验 | 图片条数/比例/体积 | 分辨率/码率/时长/字幕位置 |
| 核心指标 | 点击率、收藏率 | 完播率、完整播放时长 |
| 流量生命周期 | 15-20 天 | **90 天**（2026 扶持中长视频）|
| 初始曝光 | 基准 | **比图文高约 30%** |
| 生产耗时 | 分钟级 | 十分钟级（生成慢）|

> **双轨策略**：图文抢搜索（搜索承接好但生命周期短），视频冲推荐（长尾 90 天）。**图文爆款可二次改编成视频二次分发**。

**只分开的地方**：
| 维度 | 图文 | 视频 |
|---|---|---|
| 素材产出 | 封面+内页（多张图） | 首帧图 + 分镜视频 + 独立封面 |
| 规格校验 | 图片条数/比例/体积 | 分辨率/码率/时长/字幕位置 |
| 核心指标 | 点击率、收藏率 | 完播率、前3秒留存 |
| 生产耗时 | 分钟级 | 十分钟级（生成慢）|

```
candidate_topics ──筛选──> topics ──占用──> drafts ──生图/生视频──> assets
```

## 五、Agent 在流程中的位置

**Agent 是编排器，不是执行器。**

```
用户在对话里说"把选题#123 做成图文笔记"
  ↓ 内核自主编排（sessionId = note-123）
  skill(xhs-article-sop)   ← 加载SOP，不占常驻上下文
  → xhs_claim_topic       ← 占用
  → xhs_write_copy        ← 文案
  → xhs_gen_images        ← 生图（走后台任务，分钟级）
  → xhs_build_post        ← 组装 + 过合规
  → xhs_publish_draft     ← 投递队列（不真发布）
  done
  ↓
SSE 回推：文案文本 / 工具轨迹 / 生图进度 / 合规结果
```

**为什么值得用 Agent**：
- 人工串流程要跨 5 个页面，Agent 一次对话串完
- `job_*` 天然适合生图/生视频这类分钟级异步任务
- `subagent` 可并行处理多篇笔记
- `skill` 让 SOP 按需加载，不污染上下文

## 六、必须守住的六条设计铁律

| # | 铁律 | 原因 |
|---|---|---|
| 1 | **绝不浏览器直连内核** | 内核带 pwsh/write，直连等于给前端 shell |
| 2 | **绝不 AI 全自动发布** | 平台 2026 明确封禁 AI 托管账号（已处置 80 万+）；且风控含**鼠标行为指纹**，AI Agent 操控真实浏览器必然被识别 |
| 3 | **绝不爬虫抓笔记数据** | 官方无内容类目；**2024 年判有期徒刑三年**（破解签名）、**2025 年判赔 110 万**（数据售卖） |
| 4 | **绝不省 AI 标识** | AI 贴条不影响流量，不标识才违规；2026-08 新规扩展到账号身份 |
| 5 | **绝不生成导流话术/私信钩子** | 2025-03《交易导流违规管理细则》明令禁止，已有诉讼争议 |
| 6 | **绝不硬编码模型 ID** | 模型会批量下线（可灵 2026-09 已下线多版本），必须走 Provider 抽象层 |

## 七、技术栈推荐（含关键修正说明）

### 7.1 最终选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | **Vite 6 + React 19 + TS + Tailwind 4 + TanStack Query** | 这是登录后内部工作台，**SEO 收益为零，SSR 是纯开销**；AI 推理耗时长必须异步化，前端需独立进度轮询/流式接口 |
| 后端 | **FastAPI (Python 3.12) + SQLAlchemy 2 + Alembic** | 系统主要复杂度在 **AI 编排**，Python 生态是决定性优势（跑 LoRA、ComfyUI、transformers 内容理解）；Pydantic 自动生成前端 client |
| Agent 网关 | 与后端同进程或独立 Node 服务 | 需透传 SSE（关闭缓冲），可参考 harness README 的 Node 示例 |
| 数据库 | **PostgreSQL 16（含 pgvector）** | AI 生成元数据（模型/参数/seed/prompt/参考图）半结构化 → `jsonb`；**pgvector 是竞品分析的基础设施**（"找风格相似的爆款"） |
| 队列 | **MVP：Redis 7 + arq** → 规模化：**Temporal** | 见 7.3 |
| 对象存储 | **腾讯云 COS / 阿里云 OSS + 预签名URL** | **硬依赖，见 7.4** |
| **AI Provider 抽象层** | **自建（最容易被忽略也最重要）** | 见 7.2，必做 |
| 媒体处理 | ffmpeg | 转场/字幕/BGM 拼接走 ffmpeg，不靠模型 |
| 部署 | Docker Compose → K8s | — |

### 7.2 必须自建 AI Provider 抽象层（硬需求）

**三个不做就必然返工的理由**：

1. **模型会下线/涨价** —— 已验证：可灵 **2026-09-15 批量下线** Kling Image 1.0-2.0、1.0-2.1 视频模型、虚拟试穿 API、122 个特效模板；Seedance 折扣 10/7 到期；Seedream 已迭代 4.0→4.5→5.0。**硬编码模型 ID 必然返工**
2. **计价方式差异巨大** —— 按张/按 token/按秒/按分辨率档，必须统一折算
3. **成本可观测性只能自己做**

**必须记录的成本归因字段**：
```
provider / model / tokens或秒数 / 折算人民币 / seed / prompt版本 / 参考图ID / 是否审核失败
```
缺了这些，月底账单无法归因。

### 7.3 队列分阶段演进

| 阶段 | 方案 | 理由 |
|---|---|---|
| MVP | Redis 7 + arq | 够用，运维简单 |
| 规模化 | **Temporal** | AI 内容生产天然是**多步 saga**：选题→文案→审核→生图→审核→生视频→拼接→发布。任一步可能失败/超时/需人工介入。Temporal 每步结果持久化+回放恢复正好匹配，且支持「**暂停等待人工输入数天**」——这正是"人工审核后再继续"的刚需 |

**Temporal 代价要算进排期**：工作流代码必须确定性（读时钟/调网络要放 activity）、变更需patching 版本化、5 万事件硬上限、新人约一周上手、自建需运维 Server + 持久化存储。

❌ **Airflow 是本场景反模式**（无持久化状态语义，不适合交互式队列）。

### 7.4 对象存储是硬依赖（不是可选优化）

⚠️ **AI 服务的输入必须是公网可访问 URL，不接受 base64**（火山引擎、reAPI 等均如此）。
→ 所以**对象存储是硬依赖**。参考图用**预签名URL 限时授权**，不要永久公开读。

### 7.5 为什么不用 Next.js（修正说明）

调研中发现 Next.js 的 **RSC / Server Actions 边界迁移不可逆**——有团队离开 Next.js 时改了 1200+ 文件、加 2 万行、动 3 个仓库，之后迁到 TanStack Start 才把加载从 10-12s 降到 2-3s。

其他避坑：
- ⚠️ Next.js 16 需 Node 20.9+，middleware.ts 已更名 proxy.ts
- ⚠️ **CRA 已停止维护且有未修复 CVE，不要用**
- ❌ 不建议"本地 SQLite + 线上 Postgres"混用：jsonb/数组类型差异会浪费大量调试时间

### 7.6 成本模型（用于月度预算）

**生图**（以日均 30 篇 × 3 张 = 2,700 张/月计）：

| 方案 | 单价 | 月成本 |
|---|---|---|
| **Seedream 4.0**（火山方舟） | **¥0.2/张** | **约 ¥540** |
| Nano Banana Pro 2K | $0.134/张 | 约 ¥2,600 |

**中文提示词排名**：Seedream > 通义万相 > Nano Banana > FLUX > Midjourney
**成本差5 倍，是决定性的。** Seedream 另有"图层分解"计费档可只买背景层；**审核失败不计费**。

**生视频**（15 秒竖屏 1080P）：

| 方案 | 成本 |
|---|---|
| Vidu Q3-turbo错峰 | **¥3.8** |
| Seedance 2.0-mini 720P | ¥7.4 |
| Kling 3.0 Standard | ¥9 |
| Seedance 2.0 1080P | ¥37 |

**图生视频是必选项不是可选项** —— T2V 画面不可控，无法保证与封面/商品一致，电商不可用。**图生视频天然让"封面即首帧"**，这是与生图环节的天然衔接点。

**前置条件**：可灵 **Turbo 档只接受单首帧**，要首尾帧须用标准/Pro。注意免费档带水印且不可商用。

### 7.7 角色一致性四层方案（AI 模特技术底座）

| 层 | 方案 | 成本 | 适用 |
|---|---|---|---|
| 1 | Seed 控制 | 免费 | 同构图微调，**场景一变脸就漂** |
| 2 | **参考图**（主力）| 低 | nb2 支持 10 物体 / nbPro 5 人物 / Seedream 多图。素材需 **8-15 张标准参考集**（正/3-4侧/纯侧/多光照/多表情），**必须人工精选，畸形图会被模型吸收进身份永久复现** |
| 3 | LoRA（长期金标准）| 中 | 20-50 张精选图，kohya_ss 1000-3000 步，LR 1e-4，rank32/alpha16，RTX3090 15-25 分钟，Replicate $2-10/次 |
| 4 | 换脸兜底 | 低 | ReActor/InsightFace，永远一致但颈颌不自然 |
| 5 | ControlNet 姿态解耦 | 中 | 先用占位人生成姿态再叠 LoRA 重绘，防止模型为解 pose 而牺牲面部 |

⚠️ **不要假设 100% 一致**——模型方自己承认"Character consistency is not always perfect"。

**封面图特殊要求**：若要图内中文大标题，选 **Nano Banana Pro**（官方强调 accurate text rendering）；用 Seedream 需后期叠字。

### 7.8 发布路线的再修正（重要）

补充调研发现的**关键事实**：小红书风控是「**事后聚类**」而非实时拦截——已知反爬层次包括 `x-s`/`x-t` 签名、`acw_sc__v2` WAF、CDP 痕迹检测、Canvas/WebGL 设备指纹、**鼠标贝塞尔曲线行为指纹**、陀螺仪微抖动、同设备多账号打标。

**关键结论**：即使指纹伪装完美 + 真人账号 + 真住宅 IP，**AI Agent 操控真实浏览器仍会被识别**——反爬厂商已用mouse dynamics 直接训练分类器，**AI 与人类的运动差异是统计学差异，不是 stealth 插件能补的**。且处置是延迟+概率的（所以"昨天没事今天被封"）。

→ **花钱配环境解决不了行为层和内容层信号，而那两层才是规则原文点名的地方。**

### 7.9 数据获取：不要自研爬虫

**刑事判例（比民事判赔更严重）**：
- **2024 年陈某等三人破解小红书加密算法非法获取用户数据 → 判有期徒刑三年 + 罚金 + 没收全部违法所得**
- 2023 年柯某爬取腾讯/优酷 5 万余部作品传播 → 判刑三年 + 罚金 40 万

**自研爬虫的唯一性价比方案**是 MediaCrawler（GitHub 53.9K Star）：Playwright **不做 JS 逆向**，在已登录浏览器上下文里直接执行 JS 让浏览器自己算签名；CDP 模式复用本机登录态。

**但仍不建议作核心能力**：① 签名对抗是无底洞 ② 账号风险直接传导客户资产 ③ 商业使用的法律边界更清晰。**把预算投在数据采购上。**

**字段可得性**：

| 字段 | 第三方平台 |
|---|---|
| 笔记ID/标题/正文/图片URL/话题/作者/时间 | ✅ 可得 |
| 点赞/收藏/评论数 | ⚠️ **估算值** |
| **评论内容（含二级评论）** | 自研爬虫才行，风控最严 |
| 竞品投放金额 | 仅灰豚/千瓜 |

⚠️ 官方接口不开放，**所有第三方工具数据都是估算值，同一账号"近30天阅读"在不同工具间差异最大达 72%**。产品内必须明确标注为估算值，不用于精确 ROI。

**商用合规边界**：自家数据复盘🟢 / 行业趋势聚合🟡 / **抓原文图片直接发布或改写🔴（著作权）/ 评论做训练语料🔴 / 破解签名🔴**。

### 7.10 ⚠️ 数据平台价格不可靠（务必询价）

检索到的价格来自各家营销文章，**相互矛盾严重**：千瓜月费有 598 / 300 / 3000 三种说法，年费"数千"到"5万"跨度 10 倍。
→ **不要写进财务模型**，落地前必须实际询价。
