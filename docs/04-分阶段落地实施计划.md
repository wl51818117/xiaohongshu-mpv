# 电商工作台 · 分阶段落地实施计划

> 原则：**先跑通一条最小闭环，再横向扩链路**。每阶段都以"能验收"为终点，不做半成品堆叠。

---

## 阶段总览

| 阶段 | 目标 | 周期 | 验收标准 |
|---|---|---|---|
| **P0** | 内核工具化 + 对话闭环 | 1周 | 能用对话跑通选题→文案 |
| **P1** | 选题库+ 文案工坊 | 1.5 周 | 选题入库到成稿全人工可见 |
| **P2** | 素材工厂（生图）+ Provider 抽象层 | 2 周 | 出3:4 封面 + 内页，可挑可选 |
| **P3** | 图文链路闭环 + 发布代理 | 2 周 | 半自动发布成功 1 篇 |
| **P4** | 视频链路 | 2 周 | 出 9:16/3:4 竖版视频并发布 |
| **P5** | 数据看板 + 爆文复用 | 1.5 周 | 数据回流闭环跑通 |

**总计约 10周**（单人开发，按每阶段可独立验收切分）

---

## P0 · 内核工具化与对话闭环（第1 周）

### 目标
把 harness 从"能聊天"变成"能干活"，同时立住后端骨架。

### 任务清单

| # | 任务 | 产出 | 依赖 |
|---|---|---|---|
| 1 | 搭建 FastAPI 后端骨架 | `apps/api` 工程结构 | — |
| 2 | 接 Agent 网关（/agent/chat SSE 透传，禁止缓冲） | 前端能收到流式输出 | 1 |
| 3 | 建SQLAlchemy 模型 + Alembic（topics/drafts/assets/post_packages/publish_tasks/metrics） | 迁移文件 | 1 |
| 4 | **注册第一批 4 个内核工具**：`xhs_fetch_hot_topics` `xhs_list_topics` `xhs_claim_topic` `xhs_write_copy` | `tools/index.js` 更新 | 2,3 |
| 5 | 写第一批 2 个技能：`xhs-article-sop`、`xhs-copywriting` | `skills/*.md` | 4 |
| 6 | 前端对话窗挂 `harness-chat.js` | 能看见工具调用轨迹 | 2 |

### 关键动作
- 内核已实测在线（8787，deepseek-flash，26 工具全通），**API key 有效**，可直接用
- 会话 ID 约定：`note-{topicId}`（一个内容任务一个 session，可断线续传）
- 工具注册四约束：description 写清触发场景、返回值满足 output.schema、同步 TOOL_NAMES、execute 内try/catch

### 验收
在对话里说"查一下选题库有什么"→ 内核调`xhs_list_topics` → 返回结果并在界面显示工具轨迹。

## P1 · 选题库与文案工坊（第 2-3 周）

### 目标
跑通「选题入库 → 管理 → 筛选 → 成稿」，纯人工确认。

### 任务清单

| # | 任务 | 产出 |
|---|---|---|
| 1 | 选题库 CRUD API + 前端看板 | 选题表格（筛选/排序/状态）|
| 2 | **因子叠加生成器**（九宫格法：人群×场景×痛点×形式） | 一次产几十个候选 |
| 3 | **竞争度判定**（同题≤10篇=蓝海优先，>50篇=红海） | 自动分级 |
| 4 | 内容配比调度（干货70/热点20/人设10；流量:变现=7:3） | 配比看板 |
| 5 | 文案生成（标题≤20字且前8-13字含长尾词；正文300-800字前80字埋词） | `drafts` 表 |
| 6 | **去AI 味改写工具**（人工改≥30%） | `xhs_rewrite_copy` |
| 7 | 合规校验器（极限词/站外导流/同质化<70%/AI 标识） | 发布前拦截 |
| 8 | 文案编辑器 UI（左生成右编辑） | 可人工改 |
| 9 | 注册工具：`xhs_search_keywords` `xhs_rewrite_copy` `xhs_fetch_metrics` | — |

### 关键设计
- **2026 最重要的变化是「搜索流量+语义理解」双升级**，选题要从「追热点」转向**「长尾词布局」**
- **去 AI 味是独立环节**：口语化 + 视角转换 + 细节具体化（不完美细节：踩坑、翻车、犹豫）
- 合规校验做成硬闸：不通过不能进下一阶段
- AI 声明字段从建稿就带上，一路带到发布包
- ⚠️ **不提供任何导流话术/私信钩子生成**——产品红线

### 验收
人工在选题库挑一个选题 → 一句话让Agent 生成文案 → 去AI味 → 合规通过 → 存草稿。

---

## P2 · 素材工厂（生图）与 Provider 抽象层（第 4-5 周）

### 目标
产出符合小红书规格的封面与内页，并**把模型抽象层做出来**（不然后面必然返工）。

### 任务清单

| # | 任务 | 产出 |
|---|---|---|
| 1 | **AI Provider 抽象层**（统一生图/生视频/生文本的调用、计费、模型热切换） | `Provider` 接口 |
| 2 | **成本归因字段**（provider/model/秒数/折算人民币/seed/prompt版本/是否审核失败） | 可归因账单 |
| 3 | 接第一个 Provider（建议 Seedream 4.0，¥0.2/张，中文提示词最强） | 跑通一张图 |
| 4 | 提示词模板引擎（5 层次：主体→动作情绪→环境光影→镜头语言→风格画质） | 模板库 |
| 5 | 封面生成：3 候选 + 3:4(1080×1440) 规格强制 | 3 张候选图 |
| 6 | 内页生成：4-8 张，遵循九宫格顺序 | 图片包 |
| 7 | 规格校验器（3:4/文字≤30%/主体≥60%/单张≤10MB） | 拦截不合格图 |
| 8 | 素材库 UI（网格浏览、一键换图、下载）+对象存储 + 预签名URL | 素材可访问 |
| 9 | 异步任务接入队列（生图走后台 job） | 重试 + 进度 |
| 10 | 角色一致性：参考图方案（素材需 8-15 张标准参考集，**必须人工精选**） | 人物一致 |
| 11 | 素材新鲜度提醒（**生命周期仅 15 天**） | 超期提醒换新 |
| 12 | 注册工具：`xhs_gen_images` | — |

### 关键设计
- **Provider 抽象层是本阶段最重要的产出**。已验证：可灵 2026-09-15 批量下线 Kling Image 1.0-2.0 等模型；Seedream 已迭代 4.0→4.5→5.0。硬编码模型 ID 必然返工
- **规格校验前置到生成参数里**（prompt 就写 3:4），不要生成完再裁
- 生图是分钟级异步任务，必须走队列 + 内核 `job_*`，绝不能同步阻塞对话
- 封面出 3 候选是刚需——点击率 <2.5% 难晋级流量池，多给选择权
- ⚠️ **图内中文大标题**选 Nano Banana Pro；用 Seedream 需后期叠字
- **对象存储是硬依赖**：AI 服务输入必须是公网 URL，不接受 base64

### 验收
对一篇草稿一键生图 → 得到 3 张封面候选 + 4-8 张内页 → 全部通过规格校验 → 成本已归因到单篇。

## P3 · 图文链路闭环与发布代理（第 6-7 周）

### 目标
**跑通第一篇真实发布**——这是整个项目的第一个里程碑。

### 任务清单

| # | 任务 | 产出 |
|---|---|---|
| 1 | 组装模块：图文发布包（标题/正文/标签/图片/AI声明/POI/商品关联） | 发布包 |
| 2 | 发布前必过清单（12 项逐项校验） | 拦截报告 |
| 3 | Playwright 半自动预填（正文/标签/上传图） | 打开真实创作页 |
| 4 | 人工确认发布 + 状态回写 | `published` |
| 5 | 发布任务队列与重试 | — |
| 6 | 注册工具：`xhs_build_post` `xhs_publish_draft` `xhs_publish_status` | — |
| 7 | 发布日志与审计（谁在什么时候发了什么） | — |

### 关键设计（**本阶段最需谨慎**）
- ⚠️ **小红书风控是「事后聚类」而非实时拦截**。反爬层次：`x-s`/`x-t`签名 → `acw_sc__v2` WAF → CDP痕迹 → Canvas/WebGL 指纹 → **鼠标贝塞尔曲线行为指纹** → 陀螺仪微抖动
- **即使指纹伪装完美，AI Agent 操控真实浏览器仍会被识别**——反爬厂商已用 mouse dynamics 训练分类器，**AI 与人类的运动差异是统计学差异，不是 stealth 插件能补的**
- **Agent 绝不触碰最终提交**。`xhs_publish_draft` 只做到"打开页面填好，等人点发布"
- Playwright 用持久化登录态，人工只需点一次
- 记录操作日志，便于事后追溯（合规要求）

### 验收
工作台点"发布" → 浏览器自动打开小红书创作页并填好全部内容 → 人工核对后点发布 → 工作台状态变`published`。

## P4 · 视频链路（第 8-9 周）

### 目标
复用前 3 个模块的能力，补齐视频生产。

### 任务清单

| # | 任务 | 产出 |
|---|---|---|
| 1 | 分镜脚本生成（工具+ 技能）：0-3s钩子/3-6s可信/6-45s主体/45-60s转化 | `script[]`：镜号/画面/时长/口播/字幕 |
| 2 | 首帧图生成（复用 P2 生图） | 分镜首帧 |
| 3 | **图生视频**（不是文生视频！T2V 画面不可控，电商不可用） | 视频片段 |
| 4 | ffmpeg 拼接 + 字幕烧录（底部 15% 留空）+ BGM | 完整 mp4 |
| 5 | 独立封面生成（3:4，不用第一帧） | 视频封面 |
| 6 | 视频规格校验（9:16/1080P/码率8-12Mbps/≥25fps/前3秒钩子） | 拦截 |
| 7 | 视频发布包组装 | — |
| 8 | 注册工具：`xhs_gen_video` | — |
| 9 | 完播率 + 完整播放时长指标接入 | — |

### 关键设计
- **视频首帧复用 P2 生图能力**，实现"封面即首帧"，这是两条链路效率最大化的点
- ⚠️ **必须图生视频**：T2V 无法保证与封面/商品一致，电商场景不可用
- **2026 扶持机会**：中长视频推荐有效期 **90 天**（图文仅 15-20 天），视频初始曝光比图文高约 30%，消费时长同比 +43%
- 时长 15-60 秒，前 3 秒强钩子，**AI 单镜头 3-5 秒**，切镜 2-3 秒
- 封面必须单独出——第一帧通常是空镜，直接用会拉低点击率
- 生成耗时长，队列化 + 进度条 + 分镜级失败隔离

### 验收
一篇视频草稿 → 分镜 → 首帧图 → 视频片段 → 合成 → 校验通过 → 半自动发布成功。

---

## P5 · 数据看板与爆文复用（第 10 周）

### 目标
闭环回流，让系统越用越准。

### 任务清单

| # | 任务 | 产出 |
|---|---|---|
| 1 | 数据回流采集（发布后 1/3/7/14 天快照） | `metrics` 表 |
| 2 | 指标看板（日/周/月节奏） | 三级视图 |
| 3 | 爆文要素拆解（标题公式/结构/封面类型） | 爆文特征库 |
| 4 | **爆文复用引擎**：爆文要素 → 新选题候选 | 回流 M2 |
| 5 | 投流建议引擎（薯条：CTR≥5% 且完读≥40%；聚光：48h赞藏≥100 且 CTR≥3%） | 决策辅助 |
| 6 | 月度体检（配比7:2:1、素材 15 天生命周期、标签重合度 <60%告警） | 体检报告 |
| 7 | 淘汰机制：连续低质方向自动降权 | 选题权重调整 |

### 关键设计
- 数据快照按时间序列存，不只存最新值（要看增长曲线）
- 爆文复用是**闭环的关键**：跑得越久，选题池越准
- **评论区高频提问 → 下一批选题**，这是最省力的选题来源
- 投流只做建议，不自动执行
- ⚠️ **第三方数据都是估算值**（同一账号不同工具差 72%），产品内必须标注

### 验收
发布后的笔记数据自动回流 → 看板能看到 → 爆文要素自动生成新选题进入候选池。

## 各阶段风险与应对

| 阶段 | 风险 | 应对 |
|---|---|---|
| P0 | `setup` 回调返回 commit 载体导致内核启动失败 | 源码已注释此坑，大括号函数体不return |
| P0 | skill-filesystem 重复挂载致内核拒启动 | start-all.js 已自动修复；长期改profile 覆盖 base 行 |
| P1 | 去 AI 味效果不稳定 | 建"AI 味分"指标，反复试 prompt |
| P2 | 生图规格反复不达标 | 把规格写进 prompt 前置约束，不后置裁剪 |
| P2 | **模型批量下线**（可灵 2026-09 已发生） | Provider 抽象层 + 模型 ID 配置化 |
| P3 | **Playwright 被平台风控检测** | 保守模式 + 人工点发布；持久化登录态；不模拟高频操作 |
| P3 | **AI 行为指纹被识别** | 这正是只能半自动的原因；不做全自动 |
| P4 | 视频生成耗时长/失败率高 | 队列化 + 重试 + 分镜级失败隔离 |
| P5 | 数据回填不及时 | 定时任务 + 失败告警 |

## 建议的优先级取舍（若时间压缩）

| 优先级 | 砍什么 | 保留什么 |
|---|---|---|
| 必保 | P0-P3（图文闭环） | 图文链路是投产回报最高的 |
| 次优先 | P4 视频 | 2026 视频扶持力度大（长尾 90 天），中期价值高 |
| 可延后 | P5 爆文复用 | 人工复盘先顶上 |

**最小可用版本 = P0+P1+P2+P3**，约 7 周，产出「选题 → 文案 → 配图 → 半自动发布」的完整图文闭环。

---

## 技术风险预判（最需要盯的三件事）

1. **发布环节的风控** —— 全项目最大不确定性。建议 P3 之前先用小号做真实验证，确认半自动路线可行再投入。
2. **AI 内容标识的落地** —— 平台 API 是否支持在发布时携带 AI 声明字段，需实测确认。若不支持，则必须人工在发布页勾选（发布路径：【设置】→【内容类型声明】→ 勾选【笔记含 AI 合成内容】）。
3. **采集数据源稳定性与价格** —— 第三方数据平台价格口径混乱（千瓜月费检索到 598/300/3000 三种说法，年费跨度 10 倍），**必须实际询价**；建议抽象 Provider 接口，预留第二家。
